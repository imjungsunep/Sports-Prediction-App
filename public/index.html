About this project

This application was built with IBM Bob as part of IBM Problem Statement 28 — an AI Sports Match Predictor. IBM Bob was used as the AI engineering runtime to design, write, and refine every component described below.

Runtime services
Statistical modelPoisson + Elo blend — runs locally, deterministic, no network
Data storeSQLite (node:sqlite built-in) — 90 seeded historical records
Insight narrationGroq API · llama3-8b-8192 — LLM used for language only, not for numbers
Web serverNode.js + Express
Engineering runtimeBuilt with IBM Bob
What this model does NOT do
Provide live, real-time, or scraped match data of any kind
Use the LLM to generate probability numbers (all maths is deterministic)
Claim "RAG" without showing the retrieved records it used
Predict matches for teams with no historical data without disclosing uncertainty
Pipeline architecture
Agent 1 — Data Collection: Retrieves H2H and form records from SQLite with a date-leakage guard (no data on or after the fixture date is used).

Agent 2 — Performance Analysis: Computes recency-weighted form scores, attack/defence strength, rest days, and H2H metrics. Pure computation — no LLM.

Agent 3 — Prediction: Runs the Poisson + Elo blend model to produce calibrated win probabilities. Pure computation — no LLM.

Agent 4 — Insight Generation: Sends the pre-computed numbers and evidence records to Groq (llama3-8b-8192) to generate fan-readable insights. The LLM is instructed to cite the evidence and is forbidden from inventing statistics.
